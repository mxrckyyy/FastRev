- Phase 11 (performance) decisions: (a) **evidence first** — `PERFORMANCE_AUDIT.md` baseline (real Lighthouse JSON) was written BEFORE any code change, and every finding carries a status; lab scores are only quoted from stored run output; (b) **what got lazy and what didn't** — Auth + Dashboard + AppShell stay eager because they are the first-paint path for both landing states (guest → `/auth`, user → `/dashboard`); everything else lazy-loads; the Suspense boundary for shell routes lives inside AppShell's outlet so the chrome never unmounts (no CLS from chunk loading), focus-mode `/review` carries its own; (c) **request dedupe ≠ cache** — `useDecks` shares only the in-flight promise of concurrent identical fetches (keyed by user id); results are never stored, so create/delete/refetch semantics are byte-for-byte what they were, and a logout/login cannot join a previous user's request; (d) **declined optimizations are documented, not silent** — chart animations, font preload, `submitReview` round-trip merging (needs RPC), analytics payload, source maps all have an explicit Not-Fixed/Future-Work row with reasoning; (e) **Lighthouse stays a temp-dir install** (EALLOWSCRIPTS/`npx` risk) — run it against `vite preview` with `CHROME_PATH` pointed at system Chrome, store JSON outside the repo.

- Phase 12 (security) decisions: (a) **audit first, honest statuses** — `SECURITY_AUDIT.md` records every finding (SEC-01…SEC-26) with what was actually tested; items that need the live DB/deploy stay open and are never claimed as fixed; (b) **headers live in `vercel.json`** — the only mechanism a static SPA on Vercel has (no route handlers/middleware exist to set headers); CSP uses **no `unsafe-inline`** because the pre-paint theme bootstrap moved to `public/theme-init.js` — any future inline `<script>` would break the app in production, so add an external file instead (dev server does not apply `vercel.json`, test CSP with a static server + the header set); (c) **sanitize at render, store raw in hooks** — `friendlyDbError`/`friendlyAuthError` run where text is displayed (dev builds still log/show raw for debugging); never map errors at throw sites or inside hooks; (d) **DB hardening is defense-in-depth behind RLS, not a replacement** — triggers reject cross-user inserts/repoints and CHECKs are `NOT VALID` until executed; written but NOT run (no DB credentials here — user executes via SQL Editor, SEC-05); (e) **declined, documented** — no dependency removed or force-downgraded (mammoth `--force` would land on 0.3.29 and break `.docx` imports → accepted as SEC-14), no Edge Function introduced (static-only architecture preserved; SEC-12 documents the future per-user-quota path), API keys stay in localStorage, email confirmation stays ON, no dependency-injection/secret-scanning tooling added (manual scans + checklist instead); (f) **verification honesty** — Phase 12 claims only: lint, build, 56-check smoke, dist + git-history secret scans, and local-server + headless-Chrome header/CSP proof (inline probe blocked, full Auth render with zero violations); live-URL headers, live RLS/trigger state and logged-in flows are checklist items for the user.

- Phase 13 (cross-browser/device QA) decisions: (a) **evidence first, app vs harness separated** — `CROSS_BROWSER_QA.md` records every observed failure with its run-log evidence, and each was root-caused to either an app defect (CB-01…CB-06, fixed) or a harness/fixture/mock defect (fixed in the harness, explicitly NOT counted against the app); (b) **the harness is temp-dir only** — `run.mjs`/`dbg.mjs`/logs/screenshots live in `%TEMP%\opencode\phase13\`, never committed; the production `dist/` is served with the exact `vercel.json` header set and ALL backend/AI traffic is intercepted with deterministic fixtures, so results are reproducible and no live-backend claim is made; (c) **touch floor = the project's own 30 px `measure()` floor**, not WCAG's 24 px AA and not the 44 px AAA guidance (compact control design kept system-wide; only controls under the 30 px floor were fixed); (d) **CB-07 documented, not fixed** — `Review.handleRating`'s missing `try/finally` is unreachable in production (FSRS state is always 0–3; the stuck-ref state was reproduced only with an invalid fixture row), so touching review logic would violate the phase boundary for no real-world gain; (e) **`.single()` mock lesson** — a PostgREST mock must honor `Accept: application/vnd.pgrst.object+json` or supabase-js consumers that spread `data` silently build broken objects (the "new deck with no name" ghost); same trap will apply to any future Supabase mock.
